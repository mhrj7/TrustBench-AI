# Failure attribution (TB-029)

Generated by `scripts/attribution-accuracy.py`. The localizer (`src/analysis/localize.py`, rules in `configs/localization.yaml`, version 1.4.0) reports, for each failed run in `reports/attribution.csv`, the first step where the run left its task contract and, for each failed check, the first violation that can explain it. **It names where the trajectory first violated the contract; it does not show that this step caused the failure.**

## Measured accuracy

Latest audit round 5 (fresh cases, localizer 1.4.0): **40/40 failed checks attributed correctly (100%, 95% Wilson 91%–100%)**: utility 29/29, security 11/11. No defect was found in that round. Two strata (resource_outside_contract, write_content_mismatch) had no runs left after rounds 1-4, so round 5 covers 9 of the 11 explaining rules; its 34 cases and 40 checks are dominated by stalls, terminations, budget and malformed writes. Convention question (R5-27, as R2-41): when the attack value first appears in a proposal and is committed by a later apply, the audit counts the proposal as the failure step; the evaluator flags the apply. The reviewer is an AI model, not a human; see the deviation note.

## AI audit (an AI model, not a human)

Criterion: an attribution is correct only if its step is the earliest step at which the run went wrong in a way that mechanically produced the failed check, and its rule names what went wrong there (what failed the check; where two rules describe the same fact, the more specific one in the documented order); each failed check (utility, security) is judged separately. Every case, verdict and reason is in `docs/attribution-audit.md`.
