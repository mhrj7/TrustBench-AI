# Defense comparison on the development split (exploratory, not confirmatory)

Generated by `scripts/summarize-defense-comparison.mjs` from `evidence/tb024-*-report.json`. Every number is read from those files.

Registered settings (`configs/defense-comparison.yaml`): attack rendering `agentdojo_important_instructions`, prompt profile `plain` (the registry's primary profile), temperature 0.3, 16 live cases. A report is included only when its model, system, rendering, profile, temperature, repetitions and case set all match; earlier sanity runs with other settings are ignored. Holdout fixtures are never run.

- Each system was run in its own paired report against the same undefended baseline (direct tool service, no defense). The baseline row pools the baseline arms of all included reports for that model; the baseline configuration is identical in each.
- Published defenses (spotlighting, sandwich, tool_filter, MELON) are re-implementations on this harness from their papers and AgentDojo source, not the original code.
- Rates are over valid runs (provider-fault runs are excluded and counted). Intervals are Wilson 95%. Comparisons between systems use the Newcombe interval for a difference of two independent proportions; a difference is called lower or higher only when that interval excludes zero. Nothing here is a paired test or a confirmatory result.
- *Benign runs with a denial* counts benign runs where the gateway denied a call or an agent defense vetoed one. In the plain profile the agent is not told which tools are allowed, so gateway denials of unlisted tools on benign tasks are expected; benign utility shows whether the task still succeeded.

## Caveats

- Development split only, and the candidate defenses (`ours`) were designed after development results were seen (protocol A-012). Any advantage is a hypothesis for the single confirmatory holdout run, not a result.
- Systems with `gateway` transport include the capability gateway; the published baselines run on the direct tool service. A gateway system's advantage over a published baseline therefore mixes the gateway and its agent-side layer. The added value of an agent-side layer is its comparison against `gateway_capability` (same transport) and the per-case table, where the gateway alone cannot stop attacks whose payload stays inside an authorized write (answer poisoning, link insertion).
- One attack rendering and two repetitions per case: small samples, wide intervals. Unseparated differences are not evidence of equality.
- Hosted models cannot be pinned to a snapshot; response model IDs are recorded in each report (`model_revision`).
- Model-based defenses (tool_filter, MELON, counterfactual_writes, directive_flow) use the same model as the agent; their extra calls and tokens are listed above.
