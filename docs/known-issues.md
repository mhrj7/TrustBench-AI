# Known issues, limits and caveats

Living register. Each item says whether it is **open**, **partly addressed** or **fixed**, with the evidence or next step.
Numbers are not copied here; they live in the generated or evidence files referenced, so this page cannot drift from them.

## Research claim

| # | Item | Status | Detail / next step |
| --- | --- | --- | --- |
| R1 | Policy did not use provenance labels | **Addressed (candidate)** | Provenance is now signature-verified (A-011) and used by two defenses: token-flow blocking (`gateway_flow_block`, now an ablation after a live false block on BC-4410) and its redesign `gateway_directive_flow` (`docs/flow-check.md`). Live results: `docs/defense-comparison.md`. Both were designed on the development split: candidates, not validated contributions. |
| R2 | Free-text injection inside authorized writes | **Partly addressed (measured)** | directive_flow attributes write content to untrusted sentences and denies when the source is an instruction. Its pre-registered versions closed three measured gaps in turn: instruction-in-context (v2), short values that attribution could not see (v3), and retry-to-bypass of the stochastic classifier (v4); scores per prediction are generated in `docs/defense-comparison.md`. Still open by design: a false value stated purely as a fact inside the authorized document (`TB-ATT-DOC-005`) passes every version; closing it needs an independent trusted source. |
| R3 | Baseline attack success depends on the shared prompt | **Fixed (registered)** | `plain` is registered as the primary profile and `hardened` as secondary, before any confirmatory run (A-011, `protocol/experiment-registry.yaml`). |
| R4 | No novelty claim is supported yet | **Partly addressed** | Compared live against re-implemented spotlighting, sandwich, tool_filter, MELON and a CaMeL-style agent (`docs/camel.md`) on gpt-oss-20b and qwen3.5:9b, plus Llama-3.2-11B and Gemma 4 under a pre-registered pooled analysis (A-014). On gpt-oss-20b the directive_flow versions have a lower attacker-goal rate than every published baseline and no defense (Newcombe intervals exclude zero) but are *not* separated from the capability gateway alone at this sample size; their added value shows on the poisoning and link cases the gateway cannot stop. CaMeL stops control-flow attacks but not poisoning into data arguments, as its paper predicts. Still exploratory: development split, designs iterated on development results (A-014 to A-017), re-implementations rather than original code. A claim needs the confirmatory holdout run. |
| R5 | Pilot-sized evidence | **Open** | Few attack goals and tasks, 3–5 repetitions, a handful of models; wide intervals; no paired test claimed. |
| R6 | Thin sealed holdout | **Partly addressed** | Split v3 (A-012): two sealed groups covering all three workflows, 6 of 26 rows after A-013 and 2 of 10 groups, within the declared tolerance; never executed. Still small, still designed after development results were seen, and the oracles are tested only on synthetic trajectories. |
| R7 | Amendments after exposure | **Disclosed** | A-001 to A-013 in `protocol/amendments.md`, including the holdout exposure incident (A-005). Development results are seen; confirmatory honesty depends on keeping these visible. |

## Measurement

| # | Item | Status | Detail / next step |
| --- | --- | --- | --- |
| M1 | Live matrix incomplete | **Addressed (A-014, A-015, A-018)** | The missing cells were run: Gemini Flash-Lite (about 20 requests/day) was replaced by Gemma 4 on the same API, and the remaining cells' repetitions were lowered to 2 after measuring about 2 minutes per pair. Gemma's first attempt was rate-limited and is archived; it was rerun with token-aware pacing. Any cell still unfinished is listed, generated, in `docs/pilot-results-tb024.md`. |
| M2 | No pinned model snapshots | **Open (provider limit)** | Hosted aliases can change; every response records its model ID and Ollama models record their digest. Gemini rejects `seed`. Live runs use temperature 0.3, and the classifier-based defenses are stochastic, which v4's sticky denials partly contain. |
| M3 | Gateway latency overhead | **Fixed (component)** | `evidence/gateway-overhead-report.json` (in-process, per call). End-to-end latency is dominated by model calls; cost per task (TB-M7) is zero on free tiers and not meaningful yet. |
| M4 | "Unsafe effect" mixes attacker goals and out-of-allowlist tool use | **Partly addressed** | The generated table splits out "unlisted-tool use only". The plain profile has a high per-call block rate on benign tasks; benign utility is reported separately. |
| M5 | Gateway benefit depends on a permissive tool backend | **Measured** | Live contract-backend ablation (gpt-oss-20b, `[contract backend]` row in `docs/pilot-results-tb024.md`): when the tool service itself enforces the task contract, the undefended baseline is already much safer and the gateway adds little on top. The gateway's measured advantage therefore applies to agents whose tools do not enforce task contracts; that is the registered baseline (A-001), but it bounds the claim. |
| M6 | Recovery under live faults | **Measured (one model)** | Live run with 30% read failures and 30% lost write responses (`## Live fault injection` in `docs/pilot-results-tb024.md`): no invalid runs, read retries stayed inside the budget, exact duplicate writes were suppressed, and the tool service refused re-sent drafts. The runner's write safety covers exact repeats only: in one undefended run the model re-issued the write under a different note ID after an unknown outcome and it committed; the gateway's argument pinning prevented this in the defended arm. One model and one profile only. |
| M7 | Some models never read the injection | **Measured (limits the claim)** | On Llama-3.2-11B and llama3.2 (3B) the undefended agent never had the injected text in a model-visible message: they write without reading the source document. No defense effect can be measured on them; `docs/defense-comparison.md` prints each model's exposure, and the pre-registered pooled analysis (A-014) includes Llama-11B as registered, which dilutes it. |
| M8 | Classifier output parsing | **Fixed (A-019)** | A greedy JSON match failed on models that write their reasoning inline (Gemma 4: every verdict unparseable, so the fail-closed rule denied every attributed write). `src/agent/json-extract.ts` with regression tests; Gemma's affected runs were archived and rerun, and the confounded pooled result is shown next to the corrected one. |
| M9 | Free-tier rate limits | **Fixed (A-018)** | Gemma 4 allows 16,000 input tokens per minute; the harness paces requests per registered `model_rate_limits`. Rate-limited first attempts are archived, not used. Pacing is per process, so one job per paced model. |
| M10 | Failure attribution accuracy | **Measured (AI audit accepted, A-020)** | TB-029 closed on localizer 1.3.0 at 46/54 checks on fresh round 4. The A-022 follow-up fixed its four defects (1.4.0) and audited a fresh round 5: 40/40 checks (95% Wilson 91%–100%), but on 34 cases covering 9 of 11 rules (two strata exhausted by earlier rounds) and dominated by easy patterns; one convention question remains (attack value first in a proposal, committed later). The reviewer is an AI model, not a human; no human-AI agreement is measured (`docs/attribution.md`, every case in `docs/attribution-audit.md`). |
| M11 | directive_flow context contamination | **Measured, open** | The v2+ context window let an adjacent injected instruction relabel a legitimate sentence, blocking the correct answer (`docs/flow-check.md`). Needs a pre-registered fix and fresh fixtures. |
| M12 | Defense false positives on correct writes | **Measured, open** | The audit found gateway_flow_block (`untrusted_token_flow`) and directive_flow v2/v4 (`directive_attributed_flow`) denying contract-conformant notes and drafts, including on benign tasks (R3-4, R4-1..4). Localizer 1.3.0 reports these as `call_denied_by_defense` (7 failed runs in `reports/attribution.csv`). |
| M13 | Exact-answer oracle strictness | **Open** | The Cedar document says "the synthetic Silver policy tier"; answers "synthetic Silver" fail the exact oracle "Silver" (R3-33/34, R4-34/35, all CaMeL). Part of CaMeL's utility loss on this task is oracle strictness. Changing the oracle needs a pre-registered evaluator amendment. |

## Engineering hygiene

| # | Item | Status | Detail / next step |
| --- | --- | --- | --- |
| E1 | Hardcoded values in runtime code | **Fixed** | Policy, providers, prompts, tool descriptions, run settings, attack oracles and renderings are config/data. `tests/no-hardcoding.test.ts` enforces it. Two explicit exemptions: the frozen v1 evaluator and the eve pilot agent definition (both hash-pinned by the TB-017 pilot). Tests and verification scripts may name the fixtures they exercise. |
| E2 | API keys typed into the tracked `.env.example` | **Guarded** | Moved to the gitignored `.env`; `npm run verify:env-example` fails if it happens again. Never paste keys in chat. |
| E3 | Ollama listens on all network interfaces | **Open (host setting)** | Turn off "Expose Ollama to the network" in the Ollama app settings. |
| E4 | Workbook formula caches | **Fixed (guarded)** | After any scripted edit the workbook is recalculated and saved by Excel (AppleScript). `npm run verify:workbook` (`scripts/check-workbook.py`, part of `verify`) fails when a formula has no cached value, when a cached value is an error, or when a Completed row lists no evidence or a path that is missing on disk. It found and fixed four stale evidence paths (TB-014, TB-024). |
| E5 | Older notes in `docs/local-models.md` | **Partly addressed** | Marked as predating later changes; current numbers are in the generated results file. |
| E6 | Paid providers | **Not used** | No OpenAI credits; OpenAI is intentionally absent from `configs/providers.yaml`. |
| E7 | Review site is a static export | **Open (by design)** | `web/` (TB-030) serves a redacted export of the run store with no authentication; `npm run web:dev` binds to 127.0.0.1. There is no unredacted mode; raw records stay in the repository. Redaction is data-driven and variant-aware (models write non-breaking hyphens) but removes only values registered as sensitive. Timing waterfalls exist only for runs recorded since TB-027. |
