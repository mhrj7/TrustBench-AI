## 1. Config rollback

The bad change: approval requirement dropped from the policy (apply_record_update no longer needs an approval) (`configs/policy.yaml` `approval_required_tools`: `["apply_record_update"]` → `[]`).
Tier 1 of the release gate on the bad candidate: **FAIL** in 14.45 s (gateway_capability: 4 policy permissive changes; gateway_flow_block: 4 policy permissive changes).
Rollback: `git checkout release-tb041 -- configs` (0.26 s; configs equal the release: yes).
Rerun of the representative fixtures (the scripted development suite for both gated systems, and the smoke suite): gate **PASS** in 18.51 s.
Policy audit trail after the rollback: gateway_capability: 56 of 56 decisions identical=yes (18 changed by the bad change); gateway_flow_block: 56 of 56 decisions identical=yes (18 changed by the bad change).

**Found by this drill:** before TB-042, the gate compared only outcome verdicts. This bad change made record updates run
without their approval pause in both update cases, yet no verdict moved, so the gate passed it. Tier 1 now also compares the
policy audit trail with the committed policy traces and blocks any change that makes it more permissive (a tool executing
more often, or approved or denied less often); a test injects this exact change (`tests/release/test_injected_regressions.py`).

## 2. Service data restore

A real service process accumulated state: 3 runs, 1 guest session, 1 verified
account, 1 share link. `scripts/backup.py` took a backup **while the service was running** (0.06 s, SQLite
online backup). The data directory was then lost. A copy of the backup with one audit record altered
(`jobs/039fc263cd661d1e34106197/out/policy-traces.jsonl`, a decision changed) was refused ("backup failed verification"), and nothing was restored from it.
The real backup was restored (0.008 s) and a fresh service started on it in 0.21 s: same runs and artifact hashes,
the account signs in with its password, the guest session and the share link still work, every audit file is byte-identical,
and a new run completes.

## 3. Run-store restore

`tests/rollback/run-store.test.ts`: the durable runner was killed mid-run, its run store backed up, lost and restored, and the run resumed from the
restored copy: records [{"tool": "read_document", "status": "succeeded", "error": null, "unknown": false}, {"tool": "save_research_note", "status": "succeeded", "error": null, "unknown": false}]; the same as a control run whose store was never lost. A run killed before a write request leaves that write as outcome-unknown on resume (TB-026: never repeat a write whose effect is uncertain); a restored store keeps that behaviour too, because the intent log is restored with it.

## 4. Deployment rollback

Staging stack (`trustbench-rollback-drill`, own volume; the public demo was not touched). The current image
(`trustbench-live:2b12391`) served a run; the previous release's image (`trustbench-live:release-tb041`) replaced it on the same
volume in 6.03 s to healthy, served the same run with a byte-identical report and passed the quick deployment check;
rolling forward again took 5.9 s with the data intact.

## Procedures

- Release tags: `release-tb041` is the first; tag each release so a rollback names it.
- Config/code rollback: `git checkout <release> -- configs` (or `git revert`), then `python scripts/release-gate-scripted.py --baseline-ref <release>`.
- Public demo data: `sh deploy/backup-demo.sh` (online, to `backups/` on the project drive); restore with
  `scripts/backup.py restore --backup backups/<name> --dest <dir> --replace` into the volume while the demo is stopped.
- Deployment rollback: `TRUSTBENCH_IMAGE=trustbench-live:<release> docker compose -f deploy/compose.yaml up -d --no-build`.

## Not covered

- Recovery times are for small synthetic state (kilobytes to a few megabytes); they grow with data size. The public demo's
  first real backup: see `backup_of_public_demo` in the JSON.
- Backups live on the same drive as the data; an off-machine copy is not automated.
- A rollback across a change to the stored data format was not exercised (none exists yet between these releases).
