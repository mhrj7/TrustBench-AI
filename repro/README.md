# Reproducing TrustBench offline (TB-046)

This package lets someone else rerun the credential-free part of TrustBench from a clean clone and check that they get the
published results. Generated by `scripts/repro.py build` from `configs/repro.yaml`; do not edit by hand.

## What is published

[`manifest.json`](manifest.json) lists, with SHA-256 hashes:

- **Fixture IDs by split** (holdout 6, holdout2 24, tuning 25; split `trustbench-core-template-family-v3`). All fixtures are synthetic; the two holdouts were
  each run once and are published for re-analysis, not for rerunning.
- **Seeds:** `pair_order_seed` = 20261014, `holdout.split_seed` = 2026101401, `uncertainty.bootstrap_resamples` = 10000.
- **Configs** (44 files), **analysis scripts** (12),
  **fixtures** (6) and the **raw run records** the results are computed from (14).

Not published (`sh bin/trustbench` never needs them for the offline subset):

- `.env`: API keys (only .env.example, with empty values, is published)
- `deploy/secrets`: deployment secrets mounted into the demo container
- `backups`: demo backups: visitor sessions, accounts and runs
- `data/vendor`: the AgentDojo checkout is not redistributed; fetch-data clones the pinned commit (MIT, notice kept in third_party/licenses)
- `.tool-state`: local scratch, logs and service state
- `work`: local review scratch
- `.venv-tools`: local environment, rebuilt from the hash-pinned locks

`scripts/repro.py check` fails if any of these is tracked, if a tracked file contains a credential-shaped string or a personal
identifier, or if a hash in `manifest.json` no longer matches.

## Steps

Requirements: git, Node.js 26.5.0 with npm 12.0.0, and [uv](https://docs.astral.sh/uv/) (it installs Python 3.14.0). Or only
Docker, with the container route below. No API key, model or network access is needed after installation.

```bash
git clone --branch repro-tb046 https://github.com/mhrj7/TrustBench-AI.git
```

```bash
cd TrustBench-AI && export TRUSTBENCH_STORAGE_ROOT="$(dirname "$PWD")" npm_config_cache="$(dirname "$PWD")/.cache/npm"
```

```bash
cp .env.example .env && npm ci && sh scripts/setup-python.sh
```

```bash
.venv-tools/bin/python scripts/repro.py check && .venv-tools/bin/python scripts/repro.py reproduce
```

`reproduce` runs these steps in order:

1. fixtures, splits, sealed manifests, protocol, frozen configuration: `sh bin/trustbench validate`
2. pinned content hashes: `sh bin/trustbench manifest`
3. scripted smoke suite and arm comparison: `sh bin/trustbench smoke --check`
4. TB-033..TB-036 metrics, intervals, cost and ablations from the raw run records: `sh bin/trustbench report`
5. TB-043 related-work matrix: `.venv-tools/bin/python scripts/build-related-work.py`
6. TB-044 hypothesis test: `.venv-tools/bin/python scripts/test-hypothesis.py`
7. TB-045 full-population re-analysis (A-029): `.venv-tools/bin/python scripts/label-audit.py rerun`
8. TB-045 label audit report: `.venv-tools/bin/python scripts/label-audit.py report`
9. TB-047 technical report: every number from a stored artifact: `.venv-tools/bin/python scripts/build-report.py --check`
10. TB-048 claim boundaries: no overclaim in the public text: `.venv-tools/bin/python scripts/check-claims.py`
11. reproduction tests of the published reports: `sh bin/trustbench report --check`
12. research tests: `.venv-tools/bin/python -m pytest -q -p no:cacheprovider tests/research -k not last_recorded_reproduction`

It then compares every tracked file the steps rewrote with the committed version. Only these may differ:
Timestamps, wall-clock timings (keys ending in _ms) and random request, span and trace IDs. Everything else must be identical; SQLite files are compared by their SQL dump, not their bytes. The date line of the label-audit report may also differ. Any other difference, or any failed step,
fails the reproduction. The result is written to `repro/reproduction-log.json`.

Container route (a clean environment as a non-root user, from the files git tracks at a commit):

```bash
sh repro/run-in-container.sh <commit or tag>
```

## Result

- [`reproduction-log.json`](reproduction-log.json), 2026-10-18, commit `9b85719`, container (tracked files at the commit, non-root, no network), Linux aarch64, Python 3.14.0, Node v26.5.0: 12/12 steps passed, 0 unexpected file changes, outcome **REPRODUCED**.
- [`reproduction-log-clone.json`](reproduction-log-clone.json), 2026-10-18, commit `0c1f9d0`, fresh clone of the release tag from GitHub, documented steps on the host, Darwin arm64, Python 3.14.0, Node v26.5.0: 10/10 steps passed, 0 unexpected file changes, outcome **REPRODUCED**.

Both runs were made by the project's author: the container as a separate non-root account on Linux with no network, the
clone on the author's own machine with none of its local state. No independent person has run the package yet.

## What this does not reproduce

- **Live model runs.** The holdout results came from a hosted free model sampled at temperature 0.3. Providers change and
  retire models, and sampling varies, so a historical run cannot be replayed exactly. The package republishes the raw records
  of those runs, and every published number is recomputed from them. A new live run (`sh bin/trustbench benchmark dev-frozen`)
  needs your own free-tier key and gives new samples, not the same ones.
- **The AgentDojo-derived check** (`npm run verify:data`) needs the pinned AgentDojo checkout: `sh bin/trustbench fetch-data`
  clones it over the network.
- **The review website's browser tests** need Google Chrome; the full `npm run verify` runs them.
