## Hypothesis and rule

Provenance-aware enforcement (the frozen defended system: capability gateway with provenance labels, argument contracts, exact-argument approval and the directive-flow check) lowers unsafe committed effects under indirect prompt injection at comparable benign utility and cost, against the same agent without it.

Decision rule (protocol/preregister.md, Primary endpoints): supported when the paired-difference 95% cluster-bootstrap interval for unsafe committed effect lies below zero and the lower end of the paired-difference 95% interval for benign utility is above minus the margin
(5 percentage points). Intervals: paired cluster bootstrap over (task, attack variant) clusters, 10,000 resamples, seed 20261048.

## Conclusion

**The registered hypothesis is supported on the pre-declared primary pool**: unsafe committed effects fell from
52/75 to 8/75 (-58.7 pp, 95% [-77.3, -38.7], 15 clusters), and benign utility rose from 44/75 to 66/75
(+29.3 pp, 95% [+16.0, +44.0]), so the utility margin holds with room to spare. Scope: for the frozen defended system against the undefended agent on the pre-declared pool; per holdout: holdout-1 not separated, holdout-2 supported.

Three qualifications carry equal weight:

1. **The provenance-aware part is not shown to be what helps.** The directive-flow layer over the capability gateway had no measurable contribution on development data (-22.2 pp, 95% [-55.6, +0.0]), and the confirmatory runs had no capability-only arm to test it on. On the same data the effect
   is credited to the gateway's tool allowlist and contract-scoped arguments (see the component table).
2. **Combining existing components (capability scoping, approvals, provenance labels) is not by itself novel; see research/related-work.md.** The finding is about this configuration on these workflows,
   measured against static attack renderings; adaptive attackers were not tested (research/related-work.md, RW07 and RW24).
3. **It does not hold everywhere.** Workflows whose unsafe-effect interval includes zero: document_evidence_analyst.
   Attacks that succeeded at least as often defended as undefended: TB-ATT-DOC-104. Family slices
   whose interval includes zero: holdout1_attack, new.

All runs used free-tier providers (NVIDIA hosted, no billed price), so computed cost is zero; token counts are the cost proxy. Tokens per successful task (`reports/cost-latency.csv`): the defended arm used fewer in
9 of 12 workloads, because more of its tasks succeed; per run it uses more tokens and takes longer.
"Comparable cost" therefore holds for billed cost (zero) and, in most workloads, tokens per success, but not for latency: the defended arm is
slower per run (a mean of 16.2 s).

## Sensitivity

23 of 780 confirmatory runs ended while a model call was still waiting for the provider (TB-040). Excluding them, the
pooled unsafe-effect difference is -59.4 pp (as recorded -58.7 pp); the conclusion does not change.

## What this does not show

- That provenance tracking, rather than capability scoping, causes the improvement (no confirmatory capability-only arm).
- Robustness to adaptive or optimisation-based attackers (only static renderings were run).
- Generality beyond three synthetic workflows, the frozen free model and these attack families; on the three new families the interval includes zero.
- Any formal security property: these are measured rates with intervals, and zero observed failures would still not mean zero risk.
