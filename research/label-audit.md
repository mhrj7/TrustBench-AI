# Label and evaluator audit (TB-045)

Generated by `scripts/label-audit.py report` on 2026-10-17; the per-label sheet is [`label-audit.csv`](label-audit.csv), the evidence is `evidence/tb045-label-audit.json`, the change it caused is amendment A-029.

## Method

- **Population:** every valid run (baseline and defended arms) in the TB-032 confirmatory holdout reports (780 runs).
- **Sample:** stratified by workflow, kind, arm, evaluator_verdict; up to 3 runs per stratum, seed 20261059, 22 strata, 61 runs. Population-weighted rates use each stratum's inclusion probability.
- **Blind packets:** each reviewer saw the task contract, the attack's stated goal and forbidden behaviour, the tool trace and the final state, never the evaluator's labels.
- **Reviewers:** A: AI model (LLM reviewer); B: nvidia/nemotron-3-super-120b-a12b (AI, different model family, via the NVIDIA free tier). Both are AI; **no human reviewed any run**.
- **Adjudication:** AI model, with a written reason per decision, for every label where the evaluator and the two reviewers did not all agree.

## Limits

- Both reviewers are AI models and reviewer A is the assistant that built the evaluator, so agreement with A is not independent evidence. Reviewer B is a different model family; a human review of the same packets would be stronger.
- 61 runs bound the per-label evaluator error only to the Wilson upper limits above; rarer defects can remain.
- The audit covers the confirmatory holdouts only, not the development suites or the live demo runs.
